# API модуля ESP32 (v2) — общий для веб-панели, Android по Wi-Fi и Android по Bluetooth LE

Время — «локальное как UTC», секунды (как и раньше). Все POST принимают JSON, отвечают
`{"ok":true,"rev":N}` или `{"ok":false,"error":"…"}` с кодом 4xx/5xx.

## Состояние — `GET /api/state` (`?rev=N` → 304, если не менялось)
Поля v1 без изменений (`rev,time,device,mode,activeAlarm,snoozeUntil,duskEnd,question,volume,
next,alarms,dusk,settings,sounds`) плюс:

```jsonc
"device": {               // v1 + поле dock (нет поля — модуль ведёт часы сам)
  "dock": "device"        // "device" — в доке iPhone/iPad, часы говорят с ним, модуль отпустил линии и молчит;
                          // "passive" — линии отпущены вручную (POST /api/link {"passive":true})
},
"clock": {
  "lightOn": true,        // лампа горит (кнопка Свет / 0x4C)
  "lightLevel": 4,        // 1..20 — яркость лампы (кнопки +/− в режиме света)
  "soundOn": false,       // звук включён кнопкой Звук (играет мелодия settings.soundIdx через ЦАП)
  "test": false,          // часы в своём режиме «test» (удержание Свет 5 с)
  "pad": "light",         // к чему сейчас относятся +/− : "light" (после Свет) | "sound" (после Звук)
  "lightMode": 1, "lightLevelRaw": 1, "curve": 0   // сырые 0x4C/0x57 (диагностика)
},
"buttons": [              // последние 12 нажатий, свежие в конце
  {"ms": 630770, "id": "light", "level": 1}
],
"settings": {
  "displayBrightness": 4, "trackBedtime": true, "morningQuestion": true,   // как раньше
  "lang": "ru",           // "ru" | "en"
  "tz": "EET-2EEST,M3.5.0/3,M10.5.0/4",   // POSIX TZ
  "region": "Europe/Kyiv",                 // подпись для UI (IANA)
  "resetCombo": true,     // сброс сочетанием кнопок разрешён
  "boardLed": false,      // синий светодиод на плате модуля (индикатор состояния); по умолчанию выключен
  "soundIdx": 3,          // мелодия для кнопки Звук
  "lightOffAfterAlarm": 0 // погасить свет через N мин после выключения будильника; 0 — оставить гореть
},
"net": {
  "link": "wifi",         // как телефон связывается с модулем: "wifi" | "ble"
  "ssid": "Home", "ip": "192.168.1.61", "rssi": -52,
  "ap": false,            // true — модуль в режиме точки настройки (мастер)
  "ble": "WakeUpLight-1A2B"   // имя BLE-устройства
},
"setup": false,            // true — первичная настройка не пройдена (показать мастер)
"display": {               // табло часов
  "mode": "clock",         // "clock" | "text" | "eq"
  "text": "",              // показанная надпись (mode = "text")
  "secondsLeft": 0         // сколько осталось до возврата часов; 0 — без ограничения
},
"speaker": {               // Bluetooth-колонка (A2DP), см. «Режим колонки»
  "available": true,       // прошивка умеет быть колонкой
  "bt": false,             // модуль СЕЙЧАС в режиме колонки (тогда ответ пришёл по Bluetooth SPP)
  "on": false, "connected": false, "playing": false,   // приёмник поднят / телефон подключён / идёт музыка
  "showEq": true, "lamp": true,   // светомузыка: эквалайзер на табло, лампа по громкости
  "name": "WakeUpLight-1A2B",     // имя колонки в Bluetooth телефона
  "peer": "POCO F7 PRO",          // телефон
  "title": "…", "artist": "…"     // что играет (AVRCP; поля есть, только если телефон прислал)
}
```

Кнопки часов (`id`): `light` (Свет, level = 1 вкл / 0 выкл), `up` / `down` (+/− в режиме света,
level = новая яркость 1..20), `sound` (Звук), `volUp` / `volDown` (+/− в режиме звука),
`snooze` (Снуз), `test` (удержание Свет 5 с — вход/выход режима test).
Сырые коды cmd17 prop 0x16: 0A light, 08 up, 09 down, 07 sound, 05 volUp, 06 volDown, 04 snooze, 0B test.

## Новые команды
| Метод | Тело | Что делает |
|---|---|---|
| `POST /api/settings` | + `lang`, `tz`, `region`, `resetCombo`, `soundIdx`, `boardLed` | как раньше, новые поля по желанию |
| `POST /api/sound` | `{"on":true}` | звук вкл/выкл (как кнопка Звук) |
| `POST /api/light` | `{"on":true,"level":1..20}` | ручной свет: вкл на уровне / сменить уровень / `{"on":false}` — выкл (гаснет за ~3–5 с). Только вне рассвета/заката (иначе 409). Без полей — переключить |
| `POST /api/dusk/stop` | `{"off":true}` | остановить закат; `off` — ещё и погасить лампу, иначе она остаётся на текущей яркости |
| `POST /api/light/off` | — | погасить лампу в любом режиме: полностью за ~3–5 с, как кнопка Свет |
| `POST /api/display` | `{"text":"BOSS","sec":60}` | надпись из 4 знаков на табло на `sec` секунд (0 — пока не вернут). Знаки: 0-9, O I Z S b G B g; пробел гасит половинку только парой («  12» можно, « 1 2» нельзя) — иначе 400 с объяснением |
| `POST /api/display` | `{"eq":true,"fps":12,"sec":10}` | эквалайзер на табло (пока демо, без звука) |
| `POST /api/display` | `{"clock":true}` | вернуть часы |
| `POST /api/play` | `{"name":"sati","vol":0.4,"loop":false}` · `{"idx":3}` · `{"stop":true}` · `{"drive":1.5}` · `{"keep":false}` | мелодия из внешней флеш (mp3 → I2S → PCM5102A), открывает аудиотракт часов (58 01), пока играет — `58 02` раз в 0,5 с (без него часы глушат звук через ~2 с; `keep:false` — выключить для опытов). `drive` — мягкий ограничитель (1 = выкл) |
| `POST /api/melodies` | `{}` · `{"crc":"sati"}` · `{"format":true,"confirm":true}` | каталог мелодий во флеш, CRC32 файла (как zlib), очистка |
| `POST /api/upload?name=sati` | multipart-файл | залить мелодию во флеш (`tools/upload_melodies.py`) |
| `POST /api/flash` | `{}` · `{"test":true}` | внешняя флеш W25Q64: JEDEC ID и размер, проверка записи последнего сектора |
| `POST /api/tone` | `{"hz":440,"vol":0.3,"sec":10,"ch":"left","beep":false,"bits":32}` · `{"stop":true}` · `{"status":true}` · `{"pins":[4,21,22]}` · `{"pintest":[1,0,1]}` · `{"dc":1.5}` | тестовый тон и диагностика I2S. `dc` — постоянка на выходе ЦАП, 0..2,9 В (плавно, до перезагрузки; по умолчанию 1,5 В — вход дока часов без неё молчит) |
| `POST /api/raw` | `{"hex":"144C000A"}` | диагностика: сырой кадр часам (cmd + payload) |
| `GET /api/link` | — | счётчики линии с часами: `bytes`, `good`, `bad`, `state` (состояние×10 + неудачных подключений подряд: 0x отпущено, 1x подключение, 20 на связи, 30 уступили док), `last` — последние кадры; `dock` — автоопределение дока: `auto`, `on` (сейчас уступили), `count` (сколько раз уступали), `pulses` (повторных фронтов за стыковку), `window` (мкс пробы), `b12` [проб, «удержано», макс. мкс, последнее мкс], `b12stuck`, `lines` (уровни B11 T12 B12), `last` (последняя заметка) |
| `POST /api/link` | `{}` · `{"passive":true}` · `{"passive":false}` · `{"auto":false}` | переподключиться к часам · отпустить линии и detect вручную (режим переживает перезагрузку, сам снимается через минуту тишины от iPad) · вернуться · автоопределение iPhone/iPad в доке вкл/выкл (по умолчанию вкл, хранится в NVS) |
| `GET /api/link/lines` | — | диагностика линий detect: каждую по очереди отпустить без подтяжки / вниз / вверх и подержать 1/0 — что читается и за сколько мкс меняется. Часы видят иголки по 2 мс — сеанс может переподключиться |
| `GET /api/link/tap?rev=N` | — | только в пассивном режиме: журнал прослушки обеих линий `{"n","err","log":["номер мс C\|P hex"]}` (C — часы, P — iPad; запросы времени не пишутся; до 120 записей за ответ). |
| `POST /api/diag/shorts` | — | поиск замыканий между выводами ESP (перебор пар), затем перезагрузка |
| `POST /api/lamp` | `{"probe":true}` · `{"read":5,"n":1}` · `{"scan":[0,31]}` · `{"write":2,"hex":"00","confirm":true}` | диагностика: регистры контроллера лампы (I2C 0x51) с IO32/IO13 через преобразователь уровней; обмен только после 30 мс тишины на шине |
| `GET /api/wifi/scan` | — | `[{"ssid":"Home","rssi":-52,"secure":true}]` (может занять ~3 с) |
| `POST /api/network` | `{"ssid","pass","link":"wifi"\|"ble"}` | сохранить и перезагрузиться (ответ до перезагрузки). `pass` можно не слать — останется прежний |
| `POST /api/setup` | `{"lang","tz","region","ssid","pass","link"}` | мастер: всё сразу, `setup=false`, перезагрузка |
| `POST /api/reset` | `{"confirm":true}` | сброс к заводским: стереть всё, перезагрузка в точку настройки |
| `GET /api/events` | — | последние 100 кадров Philips `[{"ms","rx","hex"}]` (диагностика) |

## Экранный пульт (повторяет кнопки часов)
Свет → `/api/light` (переключить); + / − → если `clock.pad == "light"` — `/api/light {"level": lightLevel±1}`,
иначе `/api/volume {"v": volume±1}`; Звук → `/api/sound`; Снуз → во время звонка `/api/alarm/snooze`.

## Табло (найдено вживую 2026-10-17)
Табло рисуют сами часы из «времени», которое отдаёт модуль: каждая половинка 0..99 → две цифры, 100+ → пусто.
Модуль обновляет табло уведомлением iAP сразу, проверено до 20 раз/с. Букв у табло нет — только цифры
и похожие знаки. Эквалайзер: уровень полосы 0..5 → цифра 1, 7, 4, 3, 9, 8 (всё больше горящих сегментов).

## Свет (найдено вживую 2026-10-17)
Остановка будильника (`4F 11`) и заката (`4F 00`) замораживают лампу на текущей яркости. Погасить
программно можно только плавно: до минимума за ~3 с, полностью — через минуту (физкнопка Свет гасит за ~3 с).
Если на старте рассвета лампа горит, модуль ведёт яркость сам (кривая часов уронила бы её до минимума).

## Первичная настройка (мастер)
Нет настроек Wi-Fi или сделан сброс → модуль поднимает точку **`WakeUpLight-XXXX`**, пароль
**`wakeuplight`**, адрес **192.168.4.1**; любой адрес открывает мастер (captive portal).
Шаги: язык → регион/часовой пояс → Wi-Fi сеть (скан) → способ связи (Wi-Fi / Bluetooth) → готово.
Если сохранённая сеть недоступна 90 с после старта — точка настройки поднимается снова
(модуль при этом продолжает пытаться подключиться).

## Сброс сочетанием кнопок
- **Снуз 10 раз за 6 секунд** вне будильника (если `settings.resetCombo`) → табло мигает 3 раза → сброс.
- **Кнопка BOOT на плате ESP32**, удерживать 10 с → сброс.

## Режим колонки (Bluetooth A2DP + SPP)
Колонке и Wi-Fi вместе не хватает памяти ESP32 (без PSRAM), поэтому это **режим загрузки** (NVS `spk/mode`):
- **Wi-Fi** — обычная работа; Bluetooth выключен.
- **Колонка** — Bluetooth-приёмник A2DP («WakeUpLight-XXXX»), Wi-Fi, веб, mDNS и OTA не поднимаются. Телефон играет
  музыку через динамик часов; громкость телефона (AVRCP) = громкость часов, +/− на часах уходят телефону.
  Светомузыка: эквалайзер на табло (4 полосы) и/или лампа по громкости — пока играет музыка.
  Будильник ставит телефон на паузу. Мелодии по запросу (`/api/play`, `/api/preview`) → 409: памяти нет.

Переключение (модуль перезагружается через 1,5 с): `POST /api/speaker {"bt":true|false}` или **«Звук» 3 раза
за 3 с** на часах (вне будильника). Сам возвращается в Wi-Fi через 10 мин без телефона и после аварии
(2 аварийных перезапуска в первую минуту → безопасный режим). Итоги сеанса колонки (телефон, время, память,
SPP, звук) — первой строкой в `GET /api/events` после возврата в Wi-Fi.

`POST /api/speaker` — любые поля: `{"bt":true}` режим, `{"showEq":false}`, `{"lamp":true}` светомузыка (без перезагрузки).

**Звучание динамика (эквалайзер)** — действует на всё, что играет модуль (музыка телефона, мелодии, тон), в обоих
режимах; хранится в NVS «eq», сброс к заводским его стирает. Динамик стоит без короба: срез баса бережёт его от хрипа.
- `GET /api/state` → `"eq":{"preset":"soft","on":true,"hp":150,"body":3,"presence":0,"treble":0}`
- `POST /api/eq {"preset":"off|soft|warm|clear|loud"}` — пресет; `{"hp":50..250,"body":-6..6,"presence":-6..6,"treble":-6..6}` —
  любые поля, значения обрезаются до пределов, пресет становится `custom`. `hp` — срез 4-го порядка, Гц (≤ 50 — без среза);
  `body` — колокол 280 Гц, `presence` — 3 кГц, `treble` — полка от 8 кГц, дБ.
- Пресеты (core/eq.h): `soft` 150/+3/0/0 (по умолчанию), `warm` 120/+5/−1/−2, `clear` 200/+1/+3/+1, `loud` 200/+4/+2/0.

**Канал приложения в режиме колонки — Bluetooth SPP** (RFCOMM, UUID 1101, только спаренный телефон): строки
в том же формате, что у Bluetooth LE ниже (`{"id","m","p","b"}\n` → `{"id","code","body"}\n`). Приложение
находит часы среди подключённых к телефону колонок, при подключении шлёт `/api/time` (SNTP в этом режиме нет).

## Диагностика звука и аварий
- `POST /api/tone {"bridge":true}` — «мост»: вход дока часов дифференциальный (динамик = C506 − C505), поэтому
  L = моно, R = −моно (по умолчанию вкл). `{"dc":1.5}` — постоянка выхода ЦАП (по умолчанию 1,5 В).
- `GET /api/diag/coredump` — последняя авария из флеш: задача, PC, причина, адреса стека
  (расшифровка: `xtensa-esp32-elf-addr2line -pfiaC -e firmware.elf <адреса>` с ELF той же сборки).

## Bluetooth LE (когда `net.link = "ble"`; точка настройки и Wi-Fi при этом выключены)
Имя устройства `WakeUpLight-XXXX`. Сервис `6e7a0001-77b1-4c8e-9d1a-57a4e0c0b1a0`:
- `…0002-…` (write, write without response) — запрос: строка JSON, может приходить кусками;
  конец запроса — `\n`. `{"id":7,"m":"GET","p":"/api/state?rev=12"}` или
  `{"id":8,"m":"POST","p":"/api/alarm","b":{…}}`.
- `…0003-…` (notify) — ответ кусками по (MTU−3) байт, конец — `\n`:
  `{"id":7,"code":200,"body":{…}}` (для 304 — `"code":304`, без body).
Время модулю в BLE-режиме даёт телефон: `POST /api/time {"t": <локальное время как UTC, с>}`
(приложение шлёт при каждом подключении).

## Док: iPhone/iPad или модуль (автоопределение, проверено вживую 2026-11-03)
Модуль и устройство в доке делят одни линии (UART и detect B11/T12/B12). B12 (GPIO27) — контакт
«устройство в доке»: вставленный iPhone/iPad сажает его на землю жёстко, без устройства часы тянут его вверх.
- Пока модуль ведёт часы (держит B12 = 0), раз в секунду отпускает B12 с подтяжкой вверх на ≤100 мкс:
  без устройства линия поднимается меньше чем за 1 мкс, удержана — в доке устройство.
- 4 попадания подряд (~2 с, не раньше 15 с после старта и не во время звонка будильника) → модуль
  отпускает линии без подтяжек (B11/T12 — высокоомные, подтяжка вниз «прячет» устройство от часов),
  даёт часам фронт «вынули → вставили» (3 с), часы зовут устройство (StartIDPS) — работает как с завода.
  Смещение ЦАП на это время 0 В — звук ведёт устройство.
- Устройство молчит — ещё фронт через 8 с, дальше раз в 20 с, не больше трёх за стыковку.
- B12 высокий 2 с — устройство вынули: модуль снова ведёт часы (~2 с + подключение).
- Устройство в доке уже при включении — модуль стартует, не трогая линии.
